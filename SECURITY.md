# Security and privacy reports

## Leaked personal or confidential data

If a published entry, issue, or pull request contains **personal data, confidential material, or credentials**, yours or anyone else's:

- **If saying so publicly is harmless:** open an issue with the **Request removal** template and give only the entry id or issue number. Don't quote the sensitive content.
- **If even that would expose something sensitive:** report it privately through **[GitHub private vulnerability reporting](../../security/advisories/new)** (Security tab → *Report a vulnerability*), or by email to **CONTACT_EMAIL** *(maintainers: replace before launch)*.

Maintainers will hide or delete the issue or comment, remove the entry, and, where needed, rewrite repository history and ask GitHub Support to purge cached views. We aim to act within **72 hours**.

If you leaked your own credentials in a submission, **rotate them immediately**. Removing them from the repository does not undo the exposure.

## Vulnerabilities in the site or workflows

Examples: script injection in a workflow, a way to bypass maintainer approval, or XSS on the site. Please report privately through [GitHub private vulnerability reporting](../../security/advisories/new) rather than in a public issue. Include steps to reproduce. We will acknowledge within 7 days.

## Scope

This repository logs reports about third-party AI assistants. Report vulnerabilities in those products to their vendors, not here.
